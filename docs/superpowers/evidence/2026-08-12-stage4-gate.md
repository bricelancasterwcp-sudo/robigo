point estimate decides; no extension, no re-run, no corpus change.

## The number

**qwen2.5-coder:7b-instruct-q8_0 strict repair rate: 1.06%** — 10 passes in
940 attempts (94 records × 10 seeds, every attempt scored, zero attempt-level
exclusions).

- Record-level mean: 1.06%. Record-level 95% CI: **[0%, 3.2%]** (normal, n=94
  record pass-proportions). Cluster bootstrap on `test_id` (67 clusters,
  10,000 resamples, seed 0): **[0%, 3.5%]**.
- The gate threshold is **33.3% strict** (spec §0.2, corrected 2026-08-10
  from a mis-transcribed 40%; the `1/p ≤ 3 attempts` reasoning is the
  commitment). The entire interval sits an order of magnitude below it.

**Consequence, applied as pre-registered:** `robigo` is a
benchmark-and-findings repository. The agent is not shipped as a usable
tool. Plan 06 (stage 3, payload corruption) was gated on passing and will
not run.

"Strict" pass = target test green ∧ whole suite green ∧ anchor test file
byte-identical ∧ `outcome == "pass"` within the 8-turn cap.

## What the 10 passes were

All ten come from **one record**: `pathutils-dropped_return-183`, which
passed **10/10 seeds**. Every other record (93 of 94) passed zero. Success
is bimodal — deterministic on one easy defect, absent everywhere else — not
a thin uniform scatter. `turns_to_green_median = 7.0` (of an 8-turn cap):
even the deterministic success nearly exhausted its turns.

## Three biases, all stated (spec §10)

1. **Single-repo generality**: one corpus, one repo (boltons). The number
   describes this corpus, not "Python repair".
2. **The ~11.5k daemon ceiling** forced the 8k cap: the model never saw the
   window its training context promises. Biases against the thesis.
3. **Stage-0 probe-density pessimism** verified only 4,535 tokens of the 8k
   cap, further narrowing what the ladder could offer. Also biases against
   the thesis.

A fourth, discovered during this run:

4. **Session-harness kill**: the first Task 11 launch (13:20) was killed by
   the orchestrating session's background-task limit at 2h55m (~79% of
   calls). No numbers were read from it. The run was relaunched fully
   detached (setsid, init-parented) at 16:20 and completed cleanly (exit 0).
   The partial transcript is retained locally
   (`docs/transcripts/qwen7b-stage4.killed-20260812-1615.partial.jsonl`,
   uncommitted) for forensics only.

## Accounting defect, found and recorded

The frozen corpus contains **two distinct records named**
`jsonutils-flipped_comparison-104` (same file, operator, and line; different
mutants). `per_record` is keyed by name, so the profile fuses them into one
`[0, 20]` entry and reports `repair_records = 93` where 94 records were
attempted. Both fused records passed nothing, so the rate and interval are
unaffected; the defect is recorded in CARRIED-DEBT (record names are
descriptions, not identities). `repair_attempts = 940` is correct.

## Reading the result

The apparatus held: 940/940 attempts scored, contract violations surfaced
as infrastructure rather than model failure, the anchor file survived every
attempt, and the one mid-plan defect the dry run surfaced (per_record never
serialized — the CI above would otherwise have been uncomputable) was fixed
before the run (`72f3210`).

The thesis did not: with the instrument sound, a 7B under an honest window
budget repairs ~1% of single-defect mutants strictly, against a
pre-registered floor of 33.3%. Spec §0.2 said a null result here "is
publishable and would be the most valuable artifact in the niche." This is
that artifact: the corpus, the profiles, the transcripts, and the apparatus
that measured them.
